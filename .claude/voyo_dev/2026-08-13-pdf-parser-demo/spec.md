# PDF 图文混排解析 Demo - 产品需求规格说明（spec.md）

> 本文档为产品侧需求规格，聚焦用户可见行为、功能边界与验收口径，不涉及技术框架、技术方案与技术实现细节。

---

## 1. 背景与问题

### 1.1 PDF 解析困境

PDF 是信息密度最高、但机器解析最难的文档格式之一。同一页里常混合**正文、表格、插图、公式、扫描图片**等多种内容形态。当前团队/业务面对的典型困境：

1. **纯规则引擎的局限**：对图文混排、无边框表格、公式无力，容易出现丢内容、错顺序等问题；
2. **整页喂多模态大模型的代价**：虽然"能懂"，但成本高、速度慢、token 消耗大，且失去结构化信息；
3. **缺乏可验证的载体**：没有一个可跑、可看、可验证的载体，研发只能写脚本零散试，无法直观对比各页面类型的解析效果。

### 1.2 为何采用分层路由（产品视角）

本方案采用**分层路由**思路：先判断每一页的类型，再把每块内容分派到最适合、成本最低的处理方式——文字走原生抽取，表格走专用提取，图片区域裁剪后送多模态大模型理解，扫描件整页渲染做 OCR 与理解。

产品层面的价值：

- **成本可控**：只在真正需要"理解"的图片/扫描区域调用大模型，避免整页 token 爆炸；
- **结构保留**：文字、表格保持结构化输出，便于复用与导出；
- **效果可观测**：每一页有明确类型标签，研发可逐页对照、定位 badcase。

## 2. 目标与非目标

### 2.1 目标（Goals）

- **G1**：实现一个前端 + 后端的可运行 Demo，覆盖 PDF 四类页面的解析：纯文本、表格、图文混排、扫描件。
- **G2**：让研发能上传 PDF -> 看到逐页分类结果 -> 分块预览解析内容 -> 导出结构化结果，直观验证分层路由效果。
- **G3**：图片区域理解接入云端多模态大模型 API（OpenAI 兼容接口，可切换通义/智谱等），做到"真理解"而非 mock。
- **G4**：接口与数据模型设计清晰，便于后续从 Demo 演进为真实服务（可替换大模型、加队列、加权限）。

### 2.2 非目标（Non-Goals，本次 Demo 不做）

- ❌ 不追求生产级并发 / 高可用 / 多租户；
- ❌ 不做用户账号体系、鉴权（内部工具，Demo 阶段可无登录）；
- ❌ 不做海量 PDF 批处理管道（仅支持单文件解析，可串行多页）；
- ❌ 不内置本地多模态大模型部署（走云端 API，可后续替换）；
- ❌ 不承诺 100% 解析准确率（Demo 目标是跑通流程 + 暴露效果边界）；
- ❌ 不做结果持久化（结果存内存，按任务 ID 索引，进程重启即清空）。

### 3.1 用户画像

| 角色 | 说明 | 核心诉求 |
|------|------|----------|
| 内部研发/算法同学（主用户） | 负责解析管线研发 | 快速验证各页面类型解析效果、对比不同大模型、定位 badcase |
| Tech Lead / 评审人 | 看 Demo 决策是否投入 | 直观看到能力边界与成本 |

### 3.2 使用场景

- 研发拿到一份图文混排的样例 PDF，上传后逐页查看分类是否准确、各块解析是否正确，发现并记录 badcase；
- 评审人通过 Demo 直观感受"分层路由"在成本与效果上的权衡，决定是否进一步投入；
- 研发对比不同云端多模态大模型在图片理解、扫描件 OCR 上的表现与成本。

## 4. 用户故事

- **US1**：作为研发，我上传一份含图表混排的 PDF，希望能看到**每一页被判定为 text/table/mixed/scan 的类别**，确认分类逻辑是否准确。
- **US2**：作为研发，我希望图文混排页能**把文字和图片描述分别展示**，并知道图片在页面中的位置和顺序。
- **US3**：作为研发，我希望表格页能拿到**结构化表格**（可复制的 Markdown/CSV），而不是图片。
- **US4**：作为研发，我希望扫描件页能**走 OCR + 理解**，得到可读文字。
- **US5**：作为研发，我希望在解析**长文档**时能**看到进度**（第几页 / 各页类型），而不是卡住干等。
- **US6**：作为研发，我希望能把最终结果**导出为 Markdown 或 JSON**，方便贴到笔记/IM/其他系统继续用。

## 6. 前端交互与功能边界

### 6.1 页面与组件

**上传区**

- 支持拖拽 / 点击选择 PDF；
- 显示文件名、文件大小；
- 前端预校验：仅接受 PDF 格式，文件大小不超过 50MB，不符合时给出明确提示。

**解析状态条**

- 显示整体状态：待处理 / 解析中 / 已完成 / 部分完成 / 失败；
- 显示进度百分比与"已处理 X / 共 Y 页"。

**分页结果列表**

- 每页一张卡片，卡片头部标注"第 N 页 · 类型：mixed"；
- 卡片内按阅读顺序列出各内容块。

**内容块（Block）渲染**

- **文本块**：渲染为 Markdown 文本；保留 block 的 bbox 与 page_type 标签（可折叠展示坐标）；
- **图片块**：显示图片缩略图 + 多模态大模型描述文字 + 位置坐标（bbox）标注；
- **表格块**：按结构化数据（行列 + 合并单元格）渲染为 HTML 表格（保留 colspan/rowspan），提供"复制 Markdown"操作。

**导出按钮**

- 支持将当前结果导出为 **Markdown**（派生视图，人读）与 **JSON**（结构化真相源，保全 bbox / 合并单元格 / page_type 精度）两种文件下载。

### 6.2 状态与交互边界

- **解析中禁用重复上传**：一个任务解析进行中时，上传区禁用，避免并发干扰；
- **单页大模型失败不中断整体**：某页大模型调用失败时，该图片块标记"图片未识别（VLM 调用失败）"，页面其余内容正常展示，整体状态置为"部分完成"；
- **大文件不阻塞界面**：解析过程中前端持续刷新进度，界面始终保持可交互，不会卡死等待。

## 7. 验收标准（EARS）

### 7.1 Ubiquitous（系统始终满足的约束）

- **U1**：系统应仅接受 PDF 格式文件，拒绝其他格式并返回明确提示。
- **U2**：系统应对上传文件大小设上限（**50MB**），超限即拒绝并提示。
- **U3**：系统应在解析全程保持任务状态可追溯（待处理 -> 解析中 -> 已完成 / 部分完成 / 失败）。

### 7.2 Event-driven（事件触发）

- **E1**：当用户上传 PDF 并触发解析时，系统应创建任务并返回任务 ID，随后在后台异步开始解析。
- **E2**：当某一页解析完成时，系统应更新该任务进度与对应页结果，使前端可获取。
- **E3**：当全部页面处理完毕时，系统应将任务状态置为"已完成"或"部分完成"（存在失败页时）。

### 7.3 Unwanted（异常/故障处理）

- **X1**：如果文件损坏或无法被打开，则系统应将任务置为"失败"并返回可读错误。
- **X2**：如果某页大模型调用失败/超时，则系统应将该图片块标记为"未识别"，继续处理其余内容，整体状态置"部分完成"。
- **X3**：如果大模型返回内容异常（空/格式错），则系统应记录错误并跳过该块，不影响其他页。

### 7.4 State-driven（特定状态下行为）

- **S1**：当某页被分类为 scan 时，系统应整页渲染为图片并送大模型做 OCR + 理解。
- **S2**：当某页被分类为 table 时，系统应使用专用工具提取**结构化表格，并保留行列结构与合并单元格信息**（精度要求：不扁平化丢结构，合并单元格以 rowspan/colspan 记录）。
- **S3**：当某页被分类为 mixed 时，系统应文字原生抽取 + 图片区域裁剪送大模型。
- **S4**：当系统产出任一 block 时，应**保留该 block 的页面坐标 `bbox` 与 `page_type` 标签**于结构化结果中；markdown 视图可省略坐标，但 JSON 导出必须保留（精度要求：定位不丢）。
- **S5**：当检测到**跨页表格**时，系统应尝试将跨页断行合并为连续表格，或明确标注"跨页"边界，避免行断裂丢失结构（精度要求：跨页不丢行）。

**精度总约束**：结构化表示（`ParseResult` / `PageResult` / `Block`，含 bbox、表格单元格与合并信息、VLM 描述、page_type）是**唯一真相源**；markdown 仅为其派生视图。判定解析"精确"以结构化 JSON 为准，而非 markdown 可读性。

### 7.5 Optional（可选功能）

- **O1**：当启用"导出 Markdown/JSON"时，系统应生成对应格式文件供下载。
- **O2**：当启用"裁剪图查看"时，系统应缓存并返回图片区域原图。

## 8. 边界场景与异常处理口径

| 场景 | 现象 | 产品处理口径 |
|------|------|--------------|
| 扫描件含隐形文本层 | OCR 后嵌入不可见文本，能读到字但位置乱 | 检测文本块坐标是否异常密集/重叠；若疑似隐形层且图片为主，按扫描件处理 |
| 矢量 Logo 误判为表格 | Logo 由大量矢量线组成，线条计数高 | 加面积过滤：表格占页面较大区域，Logo 较小 |
| 图片是矢量图 | 页面有图但嵌入图片为空（SVG 风插图） | 检查矢量图形复杂度，路径极多时按图文混排处理 |
| 表格跨页 | 一页表格拆两页，单独处理断行 | 上下文记忆：上一页是表格则当前页优先按表格处理 |
| 公式识别 | LaTeX 公式在 PDF 里是碎片化字符 | 标注为公式块（Demo 仅标注，不深究） |
| 大模型超时/限流 | 云端 API 慢或限流 | 重试 1 次 + 退避；仍失败按 X2 标记未识别 |
| 超大 PDF | 解析久、占用内存 | 前端进度条；后端分页流式处理，不一次性载入全部位图 |
| 并发上传 | 多用户同时解析 | Demo **不要求并发**（单进程串行处理）；结果存**内存**（按任务 ID 索引），进程重启即清空，无需持久化 |

## 9. 数据指标与成功标准

| 指标 | 口径 | 目标（Demo 参考） |
|------|------|-------------------|
| 解析成功率 | 已完成 + 部分完成 / 总任务 | 暴露边界即可（不设硬性阈值） |
| 分类准确率 | 抽样人工核对 text/table/mixed/scan | **硬性目标 ≥ 90%**（各类型分别统计） |
| 单页平均耗时 | 各类型分别统计 | text < 0.5s，table < 2s，mixed/scan 取决于大模型 |
| 单页大模型成本 | 成本 / 调用次数 | 控制 mixed/scan 才调用大模型 |
| 端到端耗时 | 创建任务到完成 | 12 页 < 60s（视大模型） |

**成功标准**：分类准确率达 ≥ 90%（测试集每类 ≥ 20 页、人工标注核对）方视为 Demo 完成；badcase 仍需记录以便迭代。90% 为拟定门槛，具体阈值可在评审时按样本难度微调。

## 10. 已确认决策

| # | 议题 | 决策 |

| 1 | 大模型供应商与 Key | 使用**公共参数（OpenAI 兼容接口）**：预留 base_url / api_key / model 配置项，由使用者填写 key 与端点（可替换为通义/智谱/DeepSeek 等兼容服务） |
| 2 | 上传上限 | **50MB**（见验收标准 U2） |
| 3 | 并发与持久化 | **不要求并发**，单进程串行处理；结果存**内存**（按任务 ID 索引），进程重启即清空，无需落库 |
| 4 | 文本抽取默认格式 | **底层结构化精确表示为唯一真相源**（保留 bbox、表格单元格与合并信息、page_type）；对外**默认呈现/导出 markdown 视图**（人读 + LLM 友好）；因纯 markdown 会丢合并单元格/坐标/跨页结构，**导出同时提供 JSON 保全精度**（见 §7.4 精度总约束） |
| 5 | 前端形态 | **Vue 3 + Element Plus + Vite**（管理后台风格单页应用） |
| 6 | 验收口径 | **设定"分类准确率"硬性目标**：测试集每类 ≥ 20 页、人工标注核对，**分类准确率 ≥ 90%** 方视为 Demo 完成（见 §9） |

> 备注：决策 6 的 90% 为拟定门槛，具体阈值可在评审时按样本难度微调；badcase 仍需记录以便迭代。

## 11. 研发探究能力（Investigation & Evaluation）

本 Demo 定位为「可实验的探针平台」，除跑通解析流程外，还需支撑研发对以下 10 项探究的验证与调优（技术设计见 code_plan.md §11）：

| # | 探究问题 | Demo 提供的能力 |
|---|---------|---------------|
| 1 | 分类阈值调优 | 分类阈值全部 `.env` 可配（`CLS_*`），配合 #10 评测回归 |
| 2 | 隐形文本层检测 | `classify_features` 量化 overlap_rate / char_density / font_flags，可观测可回归 |
| 3 | 矢量图/表格/Logo 区分 | 特征 line_count / area_ratio / orthogonality / drawings_path_count 联合判定，可配可测 |
| 4 | 表格工具选型对比 | 可插拔 `TableExtractor`（pdfplumber / camelot / marker / mineru），eval 对比准确率/耗时 |
| 5 | 跨页表格合并策略 | 记录表头相似度 + 列对齐特征，`cross_page` 标注，供合并策略探究 |
| 6 | 多栏阅读顺序 | 栏检测（`bbox[0]` 聚类）+ 栏内 y / 栏间 x 排序，栏数写入特征 |
| 7 | VLM 成本/效果权衡 | DPI 可配、VLM 响应缓存、per-call 成本/耗时埋点（`TaskMetrics`）、**多模型注册表 + eval 模型对比** |
| 8 | 公式与特殊内容 | `probe_latex` 验证 `get_text("latex")`，`FormulaRecognizer` 可插模型 |
| 9 | 输出格式统一(IR) | 精度优先 Block 模型为统一 IR（§7.4 精度总约束） |
| 10 | 端到端评测方案 | 评测 harness：标注集 runner + 分类准确率/混淆矩阵 + 输出 diff + 回归 |

**验收**：Demo 交付时，评测 harness 可在标注样本集上输出分类准确率（总体 + 各类型）与混淆矩阵；分类阈值与表格 backend 可通过 `.env` 切换并回归对比；VLM 模型可通过 `models.json` 注册表切换并在 eval 中对比各模型的成本/耗时/描述与 OCR 质量。
